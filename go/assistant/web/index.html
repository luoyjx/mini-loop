Routines

联系人

准入分级读这张表：已知联系人直接写给你是明确请求；已知联系人抄送你、或陌生人直接写给你是推断候选，先过分诊；陌生人抄送你只归档。你批准发出的邮件会把收件人记成联系人。

画像与记忆

每晚 23:30 的「夜间整理」先由守护进程从已发送邮件学联系人、从日历算会议时间、去掉重复的记忆，再让 worker 把你当天在信道里说过的偏好记下来。画像会写进每个 worker 的提示里，只当参考。worker 还可以用 lookup 顺着 trigger / task / thread 等引用追溯一件事，试试在信道里说「追溯 trigger-1」。

记忆检索：。夜间整理会给新的或改过的记忆补几个中英文别名（右边的灰色标签），换个说法也能搜到。worker 用 memory_search 搜索，每个回合还会按事件预取最相关的 3 条放进提示。

MCP 工具

关掉进程再启动：未完成的触发器和后台准备任务会重新排队，已批准但还没发出的提案会继续发（同一幂等键，不会重复发）；任务和它的下次检查时间都在 SQLite 里，错过的检查会在启动或唤醒后补上；错过今天 07:00 的晨报会补跑一次，睡眠唤醒后也一样。「暂停处理」也会在重启后保持，直到你恢复；同一个数据目录只能有一个守护进程。

worker 用 task_create 建任务并约定检查时间；到点后 scheduler 把同一 thread 的 worker 叫醒核对进展。每个任务最多自动检查 6 次，之后交给你；连续 3 次检查要核对的内容和进展都没变，看门狗会提前把它列进「需要你处理」。

后台准备任务

worker 用 prepare_start 在后台开一个只读会话提前准备材料（一次跑一个，最多排 5 个），结果以 job.done 回到原来的 thread，由那里的 worker 决定要不要告诉你。

规则先分级：明确请求直接派工；推断候选（已知联系人抄送你、陌生人直接写给你）先过一次不带工具的分诊模型。观察模式下分诊建议处理的也只记录在这里，由你交给 worker 或忽略；自动模式下直接派工。分诊失败时一律只记录。
